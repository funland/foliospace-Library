# FolioLume × FolioSpace：影视资料库客户端 brief

日期：2026-10-10。状态：**设计建议与联调任务，不是已实现的客户端功能**。
本轮只记录方案；不修改客户端、服务接口、部署或版本号。
配套：[Docker 服务端开发计划](foliospace-video-docker-development-plan.md)。

## 1. 产品结论

推荐“选片台”：**继续看 → 找到作品 → 选择版本/集数 → 原文件播放**。
影视作品是浏览单位，文件是播放单位；连接服务器就能浏览和播放，“加入本机片库”
是可选收藏行为，不是播放前提。未匹配内容始终可用，刮削失败不是播放禁令。

不把 NAS 管理界面搬进播放器，不把首页变成海报横排的无限堆叠，也不依靠
占据首屏的大背景轮播来制造“影院感”。沉浸感留给播放和详情，选片界面优先效率。
这是一种默认信息组织上的取舍，不是声称 Emby 没有筛选或布局定制能力。
参考：Emby 官方[首页偏好说明](https://support.emby.media/support/articles/apps/common/User-Prefs-HomeScreen.html)
将 Latest Media、Continue Watching 等作为可配置首页区块；本方案不照搬配置中心。
该链接本轮搜索索引可见，全文抓取失败，不据此评价其所有现行客户端布局。

## 3. 旧客户端兼容策略（VID-01 / VID-02）

| 客户端 / 服务端组合 | 应有行为 |
| --- | --- |
| 旧客户端 + 新服务 | 原视频 ID、分页字段、manifest、文件 URL、Range、鉴权继续有效；仍显示旧文件列表 |
| 新客户端 + 旧服务 | 回退现有文件浏览与播放，不要求用户升级服务后才能看 |
| 新客户端 + 新服务 | 启用作品浏览；最终仍通过选定 videoId 获取原 manifest 播放 |

“兼容”不等于“旧 App 自动长出新布局”。当前服务端仍保留旧 thumbnail 处理，
旧 App 不会因为网页换了海报而自动采用新 artwork。建议服务端补一层非破坏性桥接：
旧 thumbnail 请求优先返回已存在的正式海报，缺失才按原路径回退；保留 URL、格式
兼容和旧帧图访问语义，不为海报浏览新增 ffmpeg 队列。上线前须测试依赖横向帧图的
旧消费者，必要时保持专用帧图路由。此桥接**尚未实现**。
旧 App 已缓存的图片可能暂时不刷新，不能承诺仅更新服务即可立即替换所有本机封面。

新客户端能力探测建议：

1. `/api/client/info` 新增可选 `capabilities.videoLibraryV1`（**建议名，尚不存在**）。
2. 缺字段时，当前 18081 这种预发布服务可做一次只读
   `GET /api/client/video-works?limit=1` 探测。200 且结构正确才启用；404/405 回退。
3. 401/403 提示认证/权限，不能当成旧服务；超时/5xx 可重试，并保留文件浏览入口。
   缓存能力结果至刷新/重连，不为每张卡片探测。不按 Docker 版本字符串推断功能。
4. 未知 JSON 字段容忍；可选展示字段缺失可降级。未知作品类型保留“文件”访问，
   不因元数据、核心 build、设备型号等创建新的播放白名单。

## 4. 客户端最小改造与请求路径

新增 `FolioSpaceWork`、`FolioSpaceWorkFile`、作品分页与能力 DTO，不把作品 id 塞进
现有 `RemoteEntry.remoteID`。本机播放、历史、收藏身份仍以 `sourceID + videoId`
定位文件；浏览实体另用 `sourceID + workId`。重新匹配/合并作品不得丢失文件历史。

| 用途 | 已存在的请求 / 约束 |
| --- | --- |
| 作品墙 | `GET /api/client/video-works?q=&kind=movie&limit=24&offset=0`，目前仅按标题/ID排序 |
| 详情 | `GET /api/client/video-works/{workId}` |
| 文件/季集 | `GET /api/client/video-works/{workId}/files?season=1&limit=24&offset=0` |
| 全部文件 | `GET /api/client/videos?limit=50&offset=0&sort=title`；包含未匹配，不是未匹配专用过滤 |
| 最近入库 | 原文件目录的 `sort=recently_added`；先显示文件，不假装是全局去重的最近作品 |
| 图像 | 使用返回的 `posterUrl`；背景现阶段 `/api/videos/{videoId}/artwork/backdrop` |
| 实际播放 | 选中文件后 `GET /api/client/videos/{videoId}/manifest`，取原始 `fileUrl` |

`Work` 当前含 id/libraryId/kind/title/year/overview/provider?/providerId?/posterUrl/videoId；
`WorkFile` 当前含 videoId/title/version/season/episode/fileUrl/format。
**没有** genres、rating、logo、HDR、音轨清单、作品总版本数、可枚举季列表或已看状态。
work.videoId 是当前 SQL 选出的代表文件（最小 videoId），不是“推荐播放版本”。
不能用它绕过版本/剧集选择。

复用现有 `AuthenticatedResource` / `ScopedHTTPClient` / `ArtworkPipeline`：

- 维持同源 Bearer 保护与反向代理前缀测试，拒绝把凭据转发给外部 artwork 域名。
- 图片按单元格像素降采样，沿用有界并发/内存缓存；懒加载可见区和小范围预取。
- 当前 artwork 返回 `private, no-cache` 和 ETag；现有图片 pipeline 主要检查 no-store，
  且缓存命中会跳过请求。需补条件重验证或明确 revision 失效，否则改图仍可能不刷新。
  新服务可选提供 `artworkRevision/artworkStatus/backdropUrl`（待开发），不要逐作品再查 metadata。
- 新接口的缺图占位目前是 SVG。原生图片解码失败应落到本机静态占位，不报整库错误、
  不对远程影片自动抽帧/探测 ISO；SVG 占位不要被当成坏影片。
- 不用 Date.now 随机 query 作为长期原生缓存策略。遵守提供方到期/清除后的失效，
  离线缓存不得无限保留 provider 内容；凭据不进入缓存 key 或日志。
- 现有客户端有明确“忽略浏览器 HLS 提示、优先原文件”的逻辑与测试，保持不变。

建议改动入口（仅定位，不代表本轮修改）：

- `Sources/XRPlayerCore/Networking/FolioSpaceClient.swift`：增量 DTO、能力探测、works/files 方法。
- `App/Networking/RemoteBrowserView.swift`、`Platforms/Shared/FlatSourceBrowser.swift`：
  仅 FolioSpace 分支按能力切换；SMB/WebDAV/Emby/Plex 不跟随改写。
- 新的 FolioSpace 作品浏览状态模型和平台薄视图；共享数据逻辑，不强行共用所有布局。
- `App/Networking/RemoteBrowserImport.swift`：保留文件身份，新增剧集导入映射，
  当前 FolioSpace 被硬映射为 movie 的地方需修正，且迁移旧条目不清库。
- `App/Artwork/ArtworkPipeline.swift`、`App/Library/PosterCard.swift`：鉴权海报、缓存失效与静态回退。
- `App/Library/LibraryStore.swift`、现有两套 PlaybackSession：保留播放链路，逐步补关联/进度。
- `Tests/XRPlayerCoreTests/NetworkSourcesTests.swift`：扩展协议矩阵，沿用原始文件/HLS回归。

## 5. 推荐布局：一个工作区，而非层层媒体目录

**主入口“片库”**：顶部是资料源与搜索；一条紧凑“继续观看”带（有本机记录才显示，
明确“本机”）；随后“近期入库”短区和主作品网格。主网格有“全部 / 电影 / 剧集”
类型控件和“作品 / 文件”切换。滚动、筛选和选中位置可恢复。
不另造“作品集”和“封面墙”两个重复导航；作品墙是同一个浏览区域。

**卡片**：海报、标题、年份；有真实数据时才显示“3 个版本”或“看到 S1E3”。
缺图使用统一占位和完整标题，不让缺海报降低可访问性。不要在每张卡片塞编码参数。
近期区与主网格重叠是不同用途，不为去重一次性扫描全库。

**选择后**：iPad/Mac/visionOS 宽窗使用旁边详情面板，主网格和滚动位置不丢；
iPhone 用可展开详情页/底部面板，不强迫两列侧栏；tvOS 用遥控器可预测的网格和详情页，
返回恢复焦点，不要求长按/悬停才能看到“版本”或“播放”。
窄屏普通字号优先两列，辅助功能大字号可切一列，不能为了数量牺牲触控和标题可读性。
不新增仅 OS 27 才可用的交互要求。

**详情优先级**：标题/年份 → 继续或播放 → 版本/季集 → 简介，背景图只作辅助。
单文件作品两步内可播放；多版本首次明确选择，之后记住该作品的文件偏好且允许更改。
用户选过的版本优先，不根据“4K”文字擅自认定设备可硬解；未知兼容性是提示不是禁用。
连入服务器即可浏览，不先“全部导入”再用本机库翻找。

**管理分离**：普通观看界面不出现 provider key、任务队列、批量匹配或清缓存按钮。
“信息不对”可打开服务端对应管理位置；有编辑权限模型之前，不宣称 App 已支持只读角色隔离。
TMDB 署名按实际使用显示；MetaTube/DMM 只是未来服务端适配器方向，不做客户端平行刮削。

P0 可做标题搜索和 movie/series；“90 分钟内 / 未看 / 年份 / 类型 / 4K / 随机挑选”
必须有完整服务端字段与全局查询支持才作为筛选发布，不能对只加载的 24 张卡片过滤后
冒充全库结果。保留熟悉的海报识别方式，用更少层级和就地详情提高效率。

## 6. 剧集专项（TV-01 至 TV-05）

### 浏览、季集与版本

数据层级为 **剧 → 季 → 集 → 版本 → videoId**，用户不必逐层点目录。
一张剧卡代表整部剧；详情默认打开最近观看的季（无历史则第一个普通季），
季切换为显式控件，下方用紧凑集列表：集号、可用标题、播放/进度、版本入口。
特别篇放“特别篇 / Season 0”，不自动排到第一集之前播放。

同一集的 1080p、4K、配音版归为版本，不显示成三集。不能按标题猜测去重文件。
当前只有分页 work/files，P0 可标“已加载 N 个文件”，**不能称 N 集或完整季数**。
待 TV-01 实现季/集分页与文件计数后，再显示“已入库 8 集 / 10 个文件”。
缺一整季时也必须能进入已入库内容，不能要求补齐再播放。

### 下一集与观看状态（TV-03 / TV-04）

本机进度先复用，跨设备进度另做 TV-03。存储最少需区分 fileId、episodeId、用户档案、
position/duration、已看标志、更新时间/修订与播放会话。不同剪辑时长不能直接复制时间点。
作品重新匹配时保留 file 历史，提供受控重关联，不把别的用户或别的剪辑进度覆盖进去。

“继续观看”优先继续未看完的那一集；明确完成或用户标已看后，才推荐下一普通集。
完成阈值是待确认产品规则，按内容长度/片尾处理，不用单一百分比把短片或开头误判完成。
支持撤销已看、重看和标记到某集；自动连播需用户开关和可取消倒计时，默认不擅自连播。
第一阶段只播放本地已有文件，不预约下载。

必须区分四种状态：本库已有 / 本库未入库 / 尚未播出 / 信息未知。
只有管理员采用了明确剧集目录、播出顺序和日期后才能判“缺集”，并注明元数据来源。
仅从本地 01、03 推断 02“缺失”是不可靠的；不把未播出或未知数量显示成缺集。

### 边界与维护

TV-02 先支持通用 SxxExx、季文件夹和安全 tvshow.nfo 继承；日期编号、动漫绝对集数、
DVD/播出顺序冲突、多集单文件、同集分段由人工映射兜底，初期不猜。
多集单文件未来需多重集关联和可选分段时间；目前不能把一份文件复制成多条可独立播放记录。
“已播/完结/总集数/下一集播出”来自有来源与时区规则的元数据，不从文件数量猜。
重扫不得覆盖人工季/集或已确认的关联。

## 7. 分阶段交付及验收

1. **P0 兼容电影/基础剧浏览**：VID-01/02，作品墙/文件回退、海报、详情、选文件播放，
   保留旧客户端；现有 files 能力只显示已有季集编号，不承诺追剧中心。
2. **P1 可用的剧集管理**：TV-01/02；真实季/集目录、多版本、人工纠错，客户端就地展开。
3. **P2 追剧与跨端状态**：TV-03/04；按档案进度、幂等/冲突策略、继续观看/下一集，
   再做 TV-05 元数据目录支持的缺集/未播提醒。每阶段可单独回退。

联合验收必须包括：

- 新旧客户端×新旧服务四组合；未知字段、空作品库、只含未匹配文件、401/403/404/5xx。
- 图片缺失/过期/修改/清除、身份切换、反代前缀和跨域 URL；不泄露 token，不永久存提供方图片。
- 浏览首屏不触发影片 Range 请求、manifest 风暴、ISO 探测或转码；分页只预取有限下一页。
- 单文件两次操作到播放；多版本多一步；返回恢复滚动/筛选/焦点，搜索取消过时响应。
- 剧两季+特别篇、同集多版本、集号不连续、未播、双集文件、错误 NFO、人工锁定与重扫。
- 两设备不同进度、离线重放事件、换版本、作品合并/解除关联、切换用户和撤销已看。
- 首屏最多一页作品请求+有限图片并发，不逐卡查 manifest；与当前真实库/千作品合成库记录
  首屏时间和内存。目标体验不是性能实测，正式指标在固定设备和网络下确认。
- iPhone/iPad/Mac/Apple TV/Vision Pro 实机输入、播放与焦点分别验收；网页通过不是原生验收。

本轮交付的是文字方案。视觉稿、客户端实施、协议开发、商店更新和 Docker 发布仍需各自授权。
