# FolioSpace Library 1.03

Release 1.03 publishes the complete movie-library P0/P1/P2 baseline while
retaining the reader, game and download functionality from 1.02.

## Movie and TV management

- Paginated poster-wall browsing and consistent artwork across the home video
  library, recently added items, works and collection surfaces.
- Local NFO/images, manual metadata corrections and explicit optional TMDB
  candidate matching. Original media files and existing video IDs remain intact.
- Work/library filters, recent sorting, stable season/episode identities,
  specials and multiple file versions for compatible clients.
- Profile/file-scoped playback state, explicit watched/unwatched, continue
  watching and next-up APIs. Idempotent retry and revision/content conflicts
  prevent silent cross-device overwrites; media delivery does not wait for sync.
- Optional on-demand refresh of a confirmed TMDB series season: locally
  available, missing, unreleased or unknown episodes, with local fallback.

The server primarily supplies catalogs, metadata, posters and original-file
streams. Clients perform decoding. Existing optional HLS compatibility is
retained; this release does not introduce background whole-library transcoding.
Client features require capability discovery and a compatible app build, not
just an image upgrade. No App Store client release is implied.

## TMDB: opt-in, operator-owned token

Online matching is off by default. Each operator must apply through their own
TMDB account and configure an **API Read Access Token**, not a v3 API key or the
FolioSpace connection token. There is no bundled/shared developer key. The 1.03
Compose example passes the optional provider/token/language settings with safe
blank defaults; real `.env` files are excluded from Git and the build context.

**Bring-your-own-token is not a commercial license.** Review TMDB's current
terms and commercial-use requirements for your actual deployment/client use,
and retain approved attribution. Do not put credentials in repositories, images,
URLs, logs, screenshots or shared Compose output. The web About screen and movie
footer include TMDB attribution. [Setup, privacy and official sources](../tmdb-setup.md)
· [中文配置说明](../tmdb-setup.zh-CN.md).

## Upgrading

1. Back up your persistent `/config` before the additive metadata/playback schema
   upgrade. Keep the existing token, data/media mounts and custom environment.
2. Pull `funland/foliospace-library:1.03` and update your existing deployment;
   use the new Compose mappings only if you want optional TMDB matching.
3. Check `/api/client/info` and your normal book/game/video workflow. Preserve
   deployment-specific startup settings, including
   `FOLIOSPACE_PRESERVE_GAME_CATALOG_ON_START=1` where already configured.
4. Keep a previous image and a stopped-state backup. Do not restore an old
   database over newly recorded progress without reconciling the changes.

```sh
docker pull funland/foliospace-library:1.03
```

Tags `1.03` and `latest` target Linux AMD64 and ARM64. Publishing an image does
not automatically replace an existing container. All earlier CIA install,
MAME/FBNeo compatibility, PC-98 per-ROM fonts, Triforce routing and Range behavior
remain included. No ROMs, BIOS, firmware, fonts, movies or private library data
are bundled.

## Documentation and acceptance boundaries

The overview now explains Reader, Player and SpatialEMU, welcomes independent
clients, and includes six real English demo captures with source/license credits.
Captured pre-release version labels remain unchanged; they do not certify a
new native client release. Client P1/P2 passed 323 Core tests and four-platform
compilation; Mac/iPad development packages were installed separately. Cross-device
playback acceptance and visionOS/tvOS device validation remain separate gates.

Legacy thumbnail-to-new-poster bridging, complex multi-episode files, and
MetaTube/DMM adapters are not delivered by this release. Existing thumbnail,
file/manifest and HLS routes remain compatible. TMDB search/refresh is explicit,
not automatic whole-library scraping. No dependency modernization is claimed.

## Release verification and known tooling warnings

Full Go tests and `go vet`, all 45 web tests, TypeScript and the production web
build passed. The Compose template passes `config --quiet` with an empty env
file. Runtime source descends from the complete accepted production baseline;
the release does not replace an existing deployment automatically.

The npm lockfile is unchanged from 1.02. Audit still reports four high-severity
dependency findings in nanoid, PostCSS, source-map-js and Vite. These concern
build/development tooling paths; the production image serves prebuilt static
assets and contains neither Node/npm nor a Vite development server. This is not
a claim that the dependency tree is vulnerability-free. Dependency remediation
remains separate, and untrusted build inputs or exposed development servers must
not be treated as safe. The existing large-JavaScript-chunk build warning also
remains; no dependency upgrade or bundle-size optimization is claimed here.
